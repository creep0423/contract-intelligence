# Real UAT Sanitization Checklist v1

## Required workflow

原始合同只能在批准的受控位置处理。脱敏副本通过复核后才能进入 `data/private_uat/`，原始文件不得进入项目目录、Git、Docker build context 或 Benchmark artifact。

## Content checklist

逐项检查并替换或移除：

- [ ] 企业名称、客户名称和供应商名称；
- [ ] 人名、签字、签名图片和手写批注；
- [ ] 电话、手机号和 Email；
- [ ] 详细地址和可定位场所信息；
- [ ] 银行账号、开户行和付款账户信息；
- [ ] 税号、身份证号和其他证件号码；
- [ ] 原始项目名称、合同编号和内部编号；
- [ ] ERP、CRM、采购单、销售单和工单编号；
- [ ] 印章、骑缝章及印章中的文字；
- [ ] 二维码、条形码和可恢复的编码图像；
- [ ] 页眉、页脚、水印、批注、修订记录和隐藏内容；
- [ ] 文件 metadata 中的作者、公司、经理、模板、最后修改人和自定义属性；
- [ ] 嵌入对象、附件、宏和外部链接中的身份信息。

## Preserve business logic

脱敏必须尽量保留：

- 百分比及金额之间的关系；
- 时间间隔和事件触发逻辑；
- 付款阶段和前置条件；
- 交货、安装、调试、验收和质保逻辑；
- 双方责任关系和违约计算方式；
- 主合同与补充协议的变更、引用和冲突关系。

可以一致性替换绝对金额或日期，但同一事实在主合同、附件、补充协议和 Gold 中必须使用同一替换映射，且不得破坏比例、阶段关系、条件关系或计算逻辑。

## File-level verification

- [ ] 打开脱敏后的每一页进行视觉复核；
- [ ] 搜索原企业名、人名、合同号和账号片段；
- [ ] 检查 OCR 文本层与图片层是否同时脱敏；
- [ ] 清理 Office/PDF metadata、批注、隐藏 sheet 和修订历史；
- [ ] 检查文件名和目录名符合匿名命名规范；
- [ ] 记录脱敏人、复核人、版本和结果，但使用匿名 reviewer ID；
- [ ] 计算私有文件 checksum，checksum 不作为公开数据反推出原文件；
- [ ] `sanitization_status` 仅在复核完成后标记为 `COMPLETED`。

## Rejection conditions

无法可靠移除真实身份、商业秘密或隐藏内容，或脱敏导致履约逻辑不可恢复时，将 `sanitization_status` 标为 `REJECTED`，不得进入 Real UAT。
